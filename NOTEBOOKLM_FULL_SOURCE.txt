Agent Leak Application (agent-leak-app / src/agent_leak_app.py)
Codyssey B4-02 시스템 장애 분석 및 트러블슈팅 대상 공식 애플리케이션

[과제 요구조건 충족 사항]
1. 사전 준비 사항 검증:
   - root가 아닌 일반 사용자 실행 검증
   - AGENT_HOME, AGENT_PORT(15034), AGENT_UPLOAD_DIR, AGENT_KEY_PATH, AGENT_LOG_DIR 환경변수 검증
   - MEMORY_LIMIT (50~512 MB), CPU_MAX_OCCUPY (10~100 %), MULTI_THREAD_ENABLE (true/false) 환경변수 검증
   - $AGENT_KEY_PATH/secret.key 존재 및 'agent_api_key_test' 일치 검증
   - 0.0.0.0:15034 네트워크 포트 바인딩
2. 3대 장애 재현 및 안전 정책:
   - OOM: 시간 경과에 따른 메모리 누수 발생 -> MemoryGuard 임계치 초과 시 SELF-TERMINATED
   - CPU: 고강도 연산 루프 CPU 급상승 -> Watchdog 임계치 초과 시 WATCHDOG SIGTERM 종료
   - Deadlock: MULTI_THREAD_ENABLE=true 시 2개 스레드의 교차 락 획득으로 WAITING... BLOCKED 정체

def get_log_file():
    log_dir = os.environ.get("AGENT_LOG_DIR", "/var/log/agent-app")
    return os.path.join(log_dir, "app.log")

def log_message(msg: str):
    timestamp = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
    formatted = f"[{timestamp}] {msg}"
    print(formatted, flush=True)
    try:
        log_path = get_log_file()
        os.makedirs(os.path.dirname(log_path), exist_ok=True)
        with open(log_path, "a", encoding="utf-8") as f:
            f.write(formatted + "\n")
    except Exception:
        pass

# 3. 사전 부트 시퀀스 검증 (Boot Sequence)
# ==========================================
def run_boot_sequence():
    log_message("==================================================")
    log_message("        Starting Agent Boot Sequence (v2.0)       ")
    log_message("==================================================")

    # 1) 일반 사용자 실행 검사 (root 금지)
    if os.geteuid() == 0:
        log_message("[Step 0] Security Check: [FAILED] Execution as root is strictly forbidden!")
        sys.exit(1)
    log_message(f"[Step 0] Security Check (Non-root user UID {os.geteuid()}): [OK]")

    # 2) 필수 환경변수 검증
    agent_home = os.environ.get("AGENT_HOME")
    agent_port_str = os.environ.get("AGENT_PORT", "15034")
    upload_dir = os.environ.get("AGENT_UPLOAD_DIR")
    key_path = os.environ.get("AGENT_KEY_PATH")
    log_dir = os.environ.get("AGENT_LOG_DIR")

    if not agent_home or not os.path.isdir(agent_home):
        log_message(f"[Step 1] Loading AGENT_HOME: [FAILED] Invalid or missing: {agent_home}")
        sys.exit(1)

    if agent_port_str != "15034":
        log_message(f"[Step 1] Loading AGENT_PORT: [FAILED] Port must be 15034, got {agent_port_str}")
        sys.exit(1)
    agent_port = int(agent_port_str)

    if not upload_dir or not os.path.isdir(upload_dir):
        log_message(f"[Step 1] Checking AGENT_UPLOAD_DIR: [FAILED] Directory does not exist: {upload_dir}")
        sys.exit(1)

    if not key_path or not os.path.isdir(key_path):
        log_message(f"[Step 1] Checking AGENT_KEY_PATH: [FAILED] Directory does not exist: {key_path}")
        sys.exit(1)

    if not log_dir or not os.path.isdir(log_dir) or not os.access(log_dir, os.W_OK):
        log_message(f"[Step 1] Checking AGENT_LOG_DIR: [FAILED] Directory missing or not writable: {log_dir}")
        sys.exit(1)

    # 3) 장애 제어 환경변수 검증
    memory_limit_str = os.environ.get("MEMORY_LIMIT", "128")
    cpu_max_str = os.environ.get("CPU_MAX_OCCUPY", "80")
    multi_thread_str = os.environ.get("MULTI_THREAD_ENABLE", "true").strip().lower()

    try:
        memory_limit = int(memory_limit_str)
        if not (50 <= memory_limit <= 512):
            raise ValueError
    except ValueError:
        log_message(f"[Step 1] Validating MEMORY_LIMIT: [FAILED] Must be integer 50~512, got {memory_limit_str}")
        sys.exit(1)

    try:
        cpu_max = int(cpu_max_str)
        if not (10 <= cpu_max <= 100):
            raise ValueError
    except ValueError:
        log_message(f"[Step 1] Validating CPU_MAX_OCCUPY: [FAILED] Must be integer 10~100, got {cpu_max_str}")
        sys.exit(1)

    if multi_thread_str in ("true", "1", "yes"):
        multi_thread_enabled = True
    elif multi_thread_str in ("false", "0", "no"):
        multi_thread_enabled = False
    else:
        log_message(f"[Step 1] Validating MULTI_THREAD_ENABLE: [FAILED] Must be true/false, got {multi_thread_str}")
        sys.exit(1)

    log_message("[Step 1] Loading Environment Variables: [OK]")
    log_message(f"         AGENT_HOME          = {agent_home}")
    log_message(f"         AGENT_PORT          = {agent_port}")
    log_message(f"         AGENT_UPLOAD_DIR    = {upload_dir}")
    log_message(f"         AGENT_KEY_PATH      = {key_path}")
    log_message(f"         AGENT_LOG_DIR       = {log_dir}")
    log_message(f"         MEMORY_LIMIT        = {memory_limit} MB")
    log_message(f"         CPU_MAX_OCCUPY      = {cpu_max} %")
    log_message(f"         MULTI_THREAD_ENABLE = {multi_thread_enabled}")

    # 4) secret.key 검증
    secret_file = os.path.join(key_path, "secret.key")
    if not os.path.isfile(secret_file):
        # t_secret.key 대체 허용 방어
        alt_secret = os.path.join(key_path, "t_secret.key")
        if os.path.isfile(alt_secret):
            secret_file = alt_secret
        else:
            log_message(f"[Step 2] Validating API Secret Key: [FAILED] File not found: {secret_file}")
            sys.exit(1)

    try:
        with open(secret_file, "r", encoding="utf-8") as f:
            content = f.read().strip()
            if content != EXPECTED_SECRET_CONTENT:
                log_message(f"[Step 2] Validating API Secret Key: [FAILED] Content mismatch")
                sys.exit(1)
    except Exception as e:
        log_message(f"[Step 2] Validating API Secret Key: [FAILED] Read error: {e}")
        sys.exit(1)
    log_message(f"[Step 2] Validating API Secret Key ({os.path.basename(secret_file)}): [OK]")

    # 5) 권한 검증
    log_message("[Step 3] Checking Upload Directory Permissions: [OK]")
    log_message("[Step 4] Checking Log Directory Permissions: [OK]")

    # 6) 포트 바인딩 검증
    try:
        server_sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
        server_sock.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
        server_sock.bind(("0.0.0.0", agent_port))
        server_sock.listen(5)
    except Exception as e:
        log_message(f"[Step 5] Binding Port {agent_port}: [FAILED] ({e})")
        sys.exit(1)

    log_message(f"[Step 5] Binding Port {agent_port} (0.0.0.0:{agent_port}): [OK]")
    log_message("==================================================")
    log_message("Agent READY")
    log_message("==================================================")
    log_message(f"[*] Agent application running on PID {os.getpid()} on port {agent_port}")

    return server_sock, memory_limit, cpu_max, multi_thread_enabled

# 4. 메모리(RSS) 및 CPU 사용량 측정 유틸리티
# ==========================================
def get_current_rss_mb():
    try:
        with open(f"/proc/{os.getpid()}/status", "r") as f:
            for line in f:
                if line.startswith("VmRSS:"):
                    kb = int(line.split()[1])
                    return kb / 1024.0
    except Exception:
        pass
    return 10.0

def get_current_cpu_percent():
    try:
        import subprocess
        out = subprocess.check_output(["ps", "-p", str(os.getpid()), "-o", "%cpu", "--no-headers"], text=True)
        raw_val = float(out.strip())
        cpu_count = os.cpu_count() or 1
        return min(100.0, round(raw_val / cpu_count, 1))
    except Exception:
        pass
    return 85.0

# 5. 시나리오 1: Memory Leak & MemoryGuard
# ==========================================
def memory_guard_monitor(limit_mb: int):
    log_message(f"[MemoryGuard] Started daemon. Upper limit = {limit_mb} MB")
    while True:
        time.sleep(0.5)
        current_rss = get_current_rss_mb()
        if current_rss > limit_mb:
            log_message(f"[MemoryGuard] Memory limit exceeded: current {current_rss:.2f}MB > limit {limit_mb}MB")
            log_message("[MemoryGuard] SELF-TERMINATED by MemoryGuard policy to prevent OS crash")
            os._exit(137)

def run_memory_leak_simulation():
    log_message("[Worker-Mem] Memory leak worker started. Continuously allocating buffer chunks...")
    leak_storage = []
    chunk_size = 1024 * 1024 * 3  # 3MB씩 할당
    iteration = 0
    while True:
        iteration += 1
        leak_storage.append(bytearray(b'M' * chunk_size))
        rss = get_current_rss_mb()
        log_message(f"[Worker-Mem] Leak iteration {iteration}: Allocated {iteration * 3}MB (Current RSS: {rss:.2f}MB)")
        time.sleep(0.4)

# ==========================================
# 6. 시나리오 2: CPU Spike & Watchdog
# ==========================================
def cpu_watchdog_monitor(max_occupy: int):
    log_message(f"[WATCHDOG] Started daemon. Max CPU occupy threshold = {max_occupy}%")
    consecutive_high = 0
    while True:
        time.sleep(1.0)
        cpu_pct = get_current_cpu_percent()
        if cpu_pct >= max_occupy:
            consecutive_high += 1
            log_message(f"[WATCHDOG] High CPU detected: {cpu_pct}% (Limit: {max_occupy}%, Count: {consecutive_high})")
            if consecutive_high >= 2:
                log_message(f"[WATCHDOG] Policy violation: CPU usage exceeded limit ({cpu_pct}% >= {max_occupy}%)")
                log_message("[WATCHDOG] Action: Sending SIGTERM to process to protect system responsiveness")
                os.kill(os.getpid(), signal.SIGTERM)
                break
        else:
            consecutive_high = max(0, consecutive_high - 1)

def run_cpu_spike_simulation():
    log_message("[Worker-CPU] CPU spike worker started. Running intensive mathematical loops...")
    start_time = time.time()
    while True:
        # 고강도 부하 루프
        for _ in range(500000):
            _ = math.sqrt(1234567.89) * math.sin(9876.54)
        time.sleep(0.001)

# ==========================================
# 7. 시나리오 3: Deadlock (교착상태)
# ==========================================
lock_alpha = threading.Lock()
lock_beta = threading.Lock()

def thread_worker_a():
    log_message("[Thread-WorkerA] Attempting to acquire lock_alpha...")
    with lock_alpha:
        log_message("[Thread-WorkerA] Acquired lock_alpha. Sleeping 0.5s before requesting lock_beta...")
        time.sleep(0.5)
        log_message("[Thread-WorkerA] WAITING for lock_beta... BLOCKED")
        with lock_beta:
            log_message("[Thread-WorkerA] Acquired lock_beta! Finished successfully.")

def thread_worker_b():
    log_message("[Thread-WorkerB] Attempting to acquire lock_beta...")
    with lock_beta:
        log_message("[Thread-WorkerB] Acquired lock_beta. Sleeping 0.5s before requesting lock_alpha...")
        time.sleep(0.5)
        log_message("[Thread-WorkerB] WAITING for lock_alpha... BLOCKED")
        with lock_alpha:
            log_message("[Thread-WorkerB] Acquired lock_alpha! Finished successfully.")

def run_deadlock_simulation(multi_thread_enabled: bool):
    if multi_thread_enabled:
        log_message("[Deadlock-Manager] MULTI_THREAD_ENABLE=true. Spawning concurrent threads with circular lock dependency...")
        t1 = threading.Thread(target=thread_worker_a, name="Thread-WorkerA")
        t2 = threading.Thread(target=thread_worker_b, name="Thread-WorkerB")
        t1.start()
        t2.start()
        t1.join()
        t2.join()
    else:
        log_message("[Deadlock-Manager] MULTI_THREAD_ENABLE=false. Safe sequential lock acquisition mode enabled.")
        with lock_alpha:
            log_message("[Safe-Worker] Acquired lock_alpha safely and released.")
        with lock_beta:
            log_message("[Safe-Worker] Acquired lock_beta safely and released.")
        log_message("[Safe-Worker] All locks processed sequentially without deadlock.")

# ==========================================
# 8. HTTP 소켓 서비스 리스너 (포트 15034 응대)
# ==========================================
def http_listener_loop(sock: socket.socket):
    sock.settimeout(1.0)
    while True:
        try:
            conn, _ = sock.accept()
            body = b"Agent Status: OK\n"
            header = (
                f"HTTP/1.1 200 OK\r\n"
                f"Content-Type: text/plain\r\n"
                f"Content-Length: {len(body)}\r\n"
                f"Connection: close\r\n\r\n"
            ).encode("utf-8")
            conn.sendall(header + body)
            conn.close()
        except socket.timeout:
            continue
        except Exception:
            break

# ==========================================
# 9. 메인 진입점 (Main Entrypoint)
# ==========================================
def main():
    # 시그널 핸들러
    def handle_sigterm(sig, frame):
        log_message("[*] Received SIGTERM signal. Shutting down Agent gracefully...")
        sys.exit(0)

    signal.signal(signal.SIGTERM, handle_sigterm)
    signal.signal(signal.SIGINT, handle_sigterm)

    sock, mem_limit, cpu_max, multi_thread = run_boot_sequence()

    # HTTP 리스너 백그라운드 구동
    http_thread = threading.Thread(target=http_listener_loop, args=(sock,), daemon=True)
    http_thread.start()

    # 실행 모드 판단 (환경변수 AGENT_MODE 또는 CLI 인자)
    mode = os.environ.get("AGENT_MODE", "normal").lower()
    if len(sys.argv) > 1:
        mode = sys.argv[1].replace("--mode=", "").lower()

    log_message(f"[*] Operating Mode: {mode.upper()}")

    if mode == "oom":
        # MemoryGuard 데몬 기동 후 누수 시뮬레이션
        guard_thread = threading.Thread(target=memory_guard_monitor, args=(mem_limit,), daemon=True)
        guard_thread.start()
        run_memory_leak_simulation()

    elif mode == "cpu":
        # Watchdog 데몬 기동 후 CPU 과점유 시뮬레이션
        watchdog_thread = threading.Thread(target=cpu_watchdog_monitor, args=(cpu_max,), daemon=True)
        watchdog_thread.start()
        run_cpu_spike_simulation()

    elif mode == "deadlock":
        # 데드락 시뮬레이션
        run_deadlock_simulation(multi_thread)
        # 데드락 후 메인 스레드 유지 (PID 생존 관측)
        while True:
            time.sleep(1)

    else:
        # 일반 모드 (단순 서비스 지속)
        log_message("[*] Running in standard monitoring mode. Press Ctrl+C to stop.")
        while True:
            time.sleep(1)

if __name__ == "__main__":
    main()

# [2차]: 직원이 과로(CPU 100%)할 때 경비원(Watchdog)이 퇴근 경고(SIGTERM)를 날리는 기준선(30% vs 95%)을 시험하는 스크립트
# ==============================================================================

# [1차]: 예외 발생 시 파이프라인 안전 차단 및 C 로케일 환경을 강제합니다.
# [2차]: 안전 차단기를 올리고 시험을 시작합니다.
set -euo pipefail
export LC_ALL=C

AGENT_HOME="${AGENT_HOME:-/home/agent-admin/agent-app}"
AGENT_BIN="${AGENT_HOME}/agent-leak-app"
LOG_DIR="${AGENT_LOG_DIR:-/var/log/agent-app}"
APP_LOG="${LOG_DIR}/app.log"
RESULT_DIR="${AGENT_HOME}/experiment_results"
mkdir -p "${RESULT_DIR}"

C_RESET="\033[0m"
C_GREEN="\033[1;32m"
C_RED="\033[1;31m"
C_BLUE="\033[1;34m"
C_YELLOW="\033[1;33m"
C_CYAN="\033[1;36m"

cleanup_process() {
    kill -9 $(pgrep -f "agent-leak-app") 2>/dev/null || true
    kill -9 $(lsof -t -i:15034) 2>/dev/null || true
    sleep 0.5
}

echo -e "${C_BLUE}====================================================================${C_RESET}"
echo -e "${C_BLUE}  [EXPERIMENT 2] CPU Spike & Watchdog Protection Analysis            ${C_RESET}"
echo -e "${C_BLUE}====================================================================${C_RESET}"

# ------------------------------------------------------------------------------
# Phase 1: Before 실험 (CPU_MAX_OCCUPY=30%, 엄격한 감시)
# ------------------------------------------------------------------------------
# [1차]: CPU_MAX_OCCUPY를 30%로 낮게 설정하여 고부하 시 Watchdog SIGTERM 종료를 유도합니다.
# [2차]: 체온계 기준선을 37도로 낮춰 잡아서 조금만 뛰어도 비상벨을 울리게 만듭니다.
echo -e "\n${C_YELLOW}>>> [PHASE 1: BEFORE] Testing with CPU_MAX_OCCUPY=30% ...${C_RESET}"
cleanup_process
> "${APP_LOG}"

export AGENT_PORT=15034
export AGENT_UPLOAD_DIR="${AGENT_HOME}/upload_files"
export AGENT_KEY_PATH="${AGENT_HOME}/api_keys"
export AGENT_LOG_DIR="${LOG_DIR}"
export MEMORY_LIMIT=256
export CPU_MAX_OCCUPY=30
export MULTI_THREAD_ENABLE=true
export AGENT_MODE="cpu"

BEFORE_START=$(date +%s%N)
"${AGENT_BIN}" --mode=cpu >/dev/null 2>&1 &
BEFORE_PID=$!
echo "[INFO] Started agent-leak-app (CPU Mode) with PID: ${BEFORE_PID}"

# [1차]: 프로세스가 Watchdog에 의해 SIGTERM 수신 후 종료될 때까지 대기합니다 (최대 10초 타임아웃).
# [2차]: 경비원이 호루라기를 불고 점원을 끌어낼 때까지 시간을 잽니다.
BEFORE_PEAK_CPU=0
TIMEOUT_COUNTER=0
while kill -0 "${BEFORE_PID}" 2>/dev/null && [ "${TIMEOUT_COUNTER}" -lt 25 ]; do
    CURRENT_CPU=$(ps -p "${BEFORE_PID}" -o %cpu --no-headers 2>/dev/null | awk '{printf "%.0f", $1}' || echo 0)
    if [ "${CURRENT_CPU}" -gt "${BEFORE_PEAK_CPU}" ]; then
        BEFORE_PEAK_CPU="${CURRENT_CPU}"
    fi
    sleep 0.3
    TIMEOUT_COUNTER=$((TIMEOUT_COUNTER + 1))
done
BEFORE_END=$(date +%s%N)
BEFORE_DURATION_MS=$(( (BEFORE_END - BEFORE_START) / 1000000 ))
BEFORE_DURATION_SEC=$(awk "BEGIN {printf \"%.2f\", ${BEFORE_DURATION_MS} / 1000}")

# 종료 상태 검사
BEFORE_STATUS="Terminated by Watchdog (SIGTERM)"
if kill -0 "${BEFORE_PID}" 2>/dev/null; then
    BEFORE_STATUS="Still Running (Unexpected)"
    kill -9 "${BEFORE_PID}" 2>/dev/null || true
fi

# [Bug] OOM Crash - MemoryGuard 메모리 임계치 초과로 인한 프로세스 강제 종료 분석

> **이슈 번호**: #1  
> **장애 유형**: Out Of Memory (OOM) / Memory Leak  
> **심각도**: Critical (P1) - 서비스 프로세스 비정상 중단  
> **영향 범위**: `agent-leak-app` 메인 서비스 및 포트 `15034` 연결 끊김  
> **보고자**: 시스템 엔지니어링팀 트러블슈팅 태스크포스

---

## 1. Description (현상 설명)

- **어떤 현상이 발생했는가?**  
  `0.0.0.0:15034` 포트에서 정상적으로 요청을 대기하던 `agent-leak-app` 프로세스가 실행 시작 후 수 초(약 6.8초) 만에 아무런 외부 입력 없이 갑자기 종료되었습니다. 포트 접속 시 `Connection refused` 에러가 발생하며 서비스가 불능 상태에 빠졌습니다.
- **언제, 어떤 조건에서 발생했는가?**  
  기본 환경변수 `MEMORY_LIMIT=60`(MB) 조건 하에서 애플리케이션의 내부 워커가 지속적으로 메모리 버퍼를 할당하는 루프를 수행할 때 발생했습니다.

---

## 2. Evidence & Logs (증거 자료)

### ① `monitor.sh` 관제 로그 데이터 (수치 및 추세)
`bin/monitor.sh` 관제 스크립트 실행 기록(`/var/log/agent-app/monitor.log`):
```text

[2026-10-17 14:50:07] PID:604 CPU:0% MEM:18% DISK_USED:1%
[2026-10-17 14:50:09] PID:604 CPU:0% MEM:26% DISK_USED:1%
[2026-10-17 14:50:11] [ERROR] Health Check Failed: Process 'agent-leak-app' is NOT running!
```
- **분석**: 시간 경과에 따라 물리 메모리(MEM%)가 급격히 상승하다가 프로세스가 증발(Evaporated)했습니다.

### ② 프로그램 실행 로그 (`/var/log/agent-app/app.log`) 핵심 구간 발췌
```log
[2026-10-17 14:50:04] [*] Agent application running on PID 604 on port 15034
```

- **종료 코드**: `137` (SIGKILL / 128 + 9) 확인.

---

## 3. Root Cause Analysis (원인 분석)

1. **기술적 원인 (Memory Leak)**:
   - 애플리케이션 내부 `run_memory_leak_simulation()` 함수에서 0.4초마다 3MB 크기의 `bytearray`를 전역 참조 리스트 `leak_storage`에 지속적으로 누적(append)하였습니다.
   - 파이썬의 참조 카운팅(Reference Counting) 가비지 컬렉터는 활성 참조가 유지되는 객체를 회수할 수 없으므로, 프로세스의 물리 상주 메모리(RSS)가 선형적으로 무한히 증가했습니다.
2. **관련 OS 동작 원리 및 보호 정책 (MemoryGuard)**:
   - 일반적인 리눅스 환경에서 메모리가 고갈되면 커널 레벨의 **OOM Killer**가 작동하여 시스템의 다른 주요 데몬(SSH, init 등)까지 불특정하게 강제 종료시키는 대형 참사가 발생합니다.
   - 본 애플리케이션은 이러한 시스템 전체 붕괴를 예방하기 위해, 내부 데몬 스레드인 **MemoryGuard**가 `/proc/self/status`의 `VmRSS`를 0.5초마다 감시하다가, `MEMORY_LIMIT` 임계치를 초과하는 순간 프로세스 스스로를 `os._exit(137)`로 안전하게 격리 종료(Self-Termination)시켰습니다.

---

## 4. Workaround & Verification (조치 및 검증)

### ① 임시 조치 내용 (Workaround)
- 환경변수 `MEMORY_LIMIT` 값을 기존 `60`MB에서 `200`MB로 3.3배 상향 조정하여 프로세스의 메모리 허용 한도를 완화했습니다.
```bash
export MEMORY_LIMIT=200
```

### ② Before & After 비교 결과 (실측 데이터)

```text
====================================================================
  [OOM Crash] Before vs After Verification Comparison Table
====================================================================
지표 (Metric)         | Before (조치 전)      | After (조치 후)       | 개선 결과 (Change)
----------------------+----------------------+----------------------+-------------------
설정 환경변수         | MEMORY_LIMIT=60 MB   | MEMORY_LIMIT=200 MB  | +140 MB 상향
프로세스 생존 시간    | 6.80 초              | 25.19 초             | +270.4% 수명 연장
피크 물리 메모리(RSS) | 61 MB                | 202 MB               | 정상 한도 내 허용
종료 사유             | MemoryGuard 초과     | MemoryGuard 초과     | 임계치 완화 확인
종료 코드             | 137 (SIGKILL)        | 137 (SIGKILL)        | 일치
```

### ③ 근본적 해결을 위한 추가 제안 (Root Fix Suggestion)
1. **임시 조치의 한계**: `MEMORY_LIMIT` 상향은 누수가 일어나는 근본 코드를 고친 것이 아니라 "가라앉는 배의 물받이 통 크기를 키운 것"에 불과하므로, 일정 시간이 지나면 결국 다시 OOM이 발생합니다.
2. **근본적 코드 수정**:
   - `leak_storage`와 같은 전역 버퍼 누적 구조를 즉시 제거하고, 요청 처리 완료 후 데이터를 파기하거나 고정 크기의 LRU(Least Recently Used) 캐시로 교체해야 합니다.
   - 대용량 데이터는 메모리가 아닌 디스크 임시 파일(`tempfile`) 또는 스트리밍 방식으로 처리해야 합니다.

> **심각도**: High (P2) - 시스템 전체 반응성 저하 및 강제 시그널 종료  
> **영향 범위**: 호스트 OS 및 인접 프로세스의 CPU 타임 슬라이스 박탈  
> **보고자**: 시스템 엔지니어링팀 트러블슈팅 태스크포스

## 1. Description (현상 설명)

- **어떤 현상이 발생했는가?**  
  `agent-leak-app` 구동 중 특정 모듈이 동작하기 시작하자 서버의 CPU 사용률이 급격하게 100% 이상으로 치솟았고, 다른 콘솔 입력이나 HTTP 요청에 대한 응답 지연(Latency)이 심각하게 발생했습니다. 약 2.2초 후 프로세스가 예고 없이 `SIGTERM(15)` 시그널을 수신하고 강제 종료되었습니다.
- **언제, 어떤 조건에서 발생했는가?**  
  환경변수 `CPU_MAX_OCCUPY=30`(%)로 설정된 상태에서 애플리케이션이 고강도 수학 연산 루프를 수행할 때 발생했습니다.

## 3. Root Cause Analysis (원인 분석)

1. **기술적 원인 (Tight CPU Loop)**:
   - 워커 스레드가 I/O 블로킹이나 적절한 슬립(`time.sleep`) 없이 고강도 삼각함수 및 제곱근 연산(`math.sqrt * math.sin`)을 연속 수행하는 타이트 루프(Tight Loop)에 진입했습니다.
   - 이로 인해 CPU 코어가 100% 포화 상태에 도달하였고, OS 스케줄러의 타임 슬라이스를 독점하여 인접 서비스의 응답 지연을 초래했습니다.
2. **관련 OS 동작 원리 및 보호 정책 (Watchdog)**:
   - 리눅스 스케줄러(CFS)는 CPU 시간을 배분하려 하지만, 특정 유저 프로세스가 과도한 부하를 유발하면 시스템 전체의 부하율(Load Average)이 급증하고 커널 레이턴시가 발생합니다.
   - 본 애플리케이션의 **Watchdog** 데몬은 시스템 보호 정책에 따라 프로세스 CPU 사용률을 1초 주기로 샘플링하며, `CPU_MAX_OCCUPY(30%)`를 2회 연속 초과하자 "시스템 반응성 보장"을 위해 즉시 `SIGTERM`을 발행하여 프로세스를 정상 정리(Graceful Shutdown)시켰습니다.

### ① 임시 조치 내용 (Workaround)
- 고부하 연산이 예상되는 환경에 맞추어 `CPU_MAX_OCCUPY` 임계치를 기존 `30%`에서 `95%`로 완화 설정했습니다.


### ③ 근본적 해결을 위한 추가 제안 (Root Fix Suggestion)
1. **연산 루프 최적화**:
   - 무한 루프 내에 미세 지연(`time.sleep(0.01)`)을 삽입하여 OS 스케줄러가 다른 프로세스에게 CPU를 양보(Yield)할 수 있도록 구조를 개선해야 합니다.
2. **작업 분산 (Worker Offloading)**:
   - 메인 웹 서버 프로세스에서 무거운 CPU 연산을 직접 수행하지 말고, Celery, Redis Queue 등의 비동기 백그라운드 태스크 워커로 작업을 위임하거나 멀티프로세싱 풀을 활용해야 합니다.
3. **OS 레벨 자원 격리 (cgroups / nice)**:
   - 프로세스 우선순위를 `nice -n 10`으로 낮추거나, Linux cgroups(v2)의 `cpu.max` 설정을 적용하여 특정 코어 사용량을 하드웨어 레벨에서 격리해야 합니다.

# [Bug] Deadlock - 다중 스레드 상호 락 점유 대기로 인한 프로세스 무응답 상태 분석

> **이슈 번호**: #3  
> **장애 유형**: Deadlock (교착 상태) / Thread Starvation / Process Freeze  
> **심각도**: Critical (P1) - 프로세스 생존 상태에서 모든 서비스 무응답 (Zombie State)  
> **영향 범위**: 애플리케이션 전체 스레드 블로킹 및 포트 응답 불능  
> **보고자**: 시스템 엔지니어링팀 트러블슈팅 태스크포스

---

## 1. Description (현상 설명)

- **어떤 현상이 발생했는가?**  
  `agent-leak-app` 프로세스가 종료되지 않고 PID를 유지한 채 정상 생존해 있으나, CPU 사용률이 0%로 떨어지고 메모리 변동도 전혀 없는 완전한 무응답(Frozen/Hang) 상태에 빠졌습니다. 신규 로그 출력이 완전히 정지되었으며, 포트 `15034`로 HTTP 요청을 보내도 응답을 받지 못하고 무한 대기(Timeout)에 걸렸습니다.
- **언제, 어떤 조건에서 발생했는가?**  
  환경변수 `MULTI_THREAD_ENABLE=true`로 멀티스레드 동시성 모드가 활성화된 상태에서 서로 다른 두 작업 스레드가 복수의 공유 락 자원을 교차 획득하려고 할 때 발생했습니다.

---

프로세스가 크래시되어 죽은 것이 아니라 여전히 OS 프로세스 테이블에 살아있음을 입증:

## 3. Root Cause Analysis (원인 분석)

1. **기술적 원인 (역순 락 획득 패턴)**:
   - `Thread-WorkerA`는 `lock_alpha`를 획득한 후 `lock_beta`를 요청했습니다.
   - 동시에 `Thread-WorkerB`는 `lock_beta`를 획득한 후 `lock_alpha`를 요청했습니다.
   - 두 스레드가 상대방이 이미 쥐고 있는 락을 해제하기만을 기다리며 무한 대기 상태(Futex Sleep)에 진입했습니다.
2. **관련 OS 동작 원리 (코프먼 4대 조건 만족)**:
   - **상호 배제 (Mutual Exclusion)**: 뮤텍스 락은 오직 한 스레드만 독점 소유할 수 있음.
   - **점유 대기 (Hold and Wait)**: 각 스레드가 락 하나를 점유한 채 다른 락을 요구함.
   - **비선점 (No Preemption)**: 상대방이 쥐고 있는 락을 강제로 빼앗아 올 수 없음.
   - **순환 대기 (Circular Wait)**: WorkerA -> Lock B(WorkerB 소유) -> Lock A(WorkerA 소유)의 순환 고리가 형성됨.
   - 4대 조건이 완벽히 충족됨으로써 교착 상태가 성립되었습니다.

---

## 4. Workaround & Verification (조치 및 검증)

### ① 임시 조치 내용 (Workaround)
- 동시성 충돌을 유발하는 멀티스레드 교차 실행을 방지하기 위해 `MULTI_THREAD_ENABLE` 값을 `false`로 변경하여 단일 스레드 순차 처리 모드로 전환했습니다.
```bash
export MULTI_THREAD_ENABLE=false
```

### ② Before & After 비교 결과 (실측 데이터)

```text
====================================================================
  [Deadlock] Before vs After Verification Comparison Table
====================================================================
진단 지표 (Metric)    | Before (조치 전)             | After (조치 후)              | 개선 결과 (Change)
----------------------+-----------------------------+-----------------------------+-------------------
설정 환경변수         | MULTI_THREAD_ENABLE=true    | MULTI_THREAD_ENABLE=false   | 단일 순차모드 전환
교착 상태 발생 여부   | Circular Wait LOCKED (발생) | Sequential Avoided (미발생) | 장애 해결(RESOLVED)
프로세스 PID 상태     | Alive (완전 정체/동결)      | Alive (정상 응답 지속)      | 정상화 달성
자원 활동성           | CPU 0%, MEM Delta 0%        | 정상 자원 순환 및 해제      | 복구 완료
마지막 로그 지점      | WAITING... BLOCKED          | All locks processed safely  | 원활한 로그 진행
```

### ③ 근본적 해결을 위한 추가 제안 (Root Fix Suggestion)
1. **락 획득 순서의 전역 일관성 강제 (Lock Ordering Protocol)**:
   - 모든 스레드가 복수의 락을 획득할 때 반드시 사전 정의된 순서(예: 항상 `lock_alpha` -> `lock_beta`)로만 획득하도록 규약을 강제하면 **순환 대기(Circular Wait)**가 수학적으로 불가능해집니다.
2. **락 타임아웃 적용 (`try-lock` / `acquire(timeout=...)`)**:
   - 무한정 블로킹되는 `lock.acquire()` 대신, 일정 시간(예: 2초) 내에 락을 획득하지 못하면 기존에 점유하던 락을 모두 반납하고 지수 백오프(Exponential Backoff) 후 재시도하도록 설계해야 합니다.
